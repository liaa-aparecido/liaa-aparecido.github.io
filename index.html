00 · Contexto

Um firewall real. Alertas reais. Risco real.

OPNsense 26.7.8 em produção com política blacklist + default deny. Suricata 8.0.8 em modo IDS na interface WAN — vê o pacote antes do PF decidir.

O ambiente

  • eve.json — 48.915 alertas do Suricata (7 dias)
  • filterlog — 473.304 linhas do PF (31 dias)
  • crowdsec_blocklists — 8.328 IPs em tempo real
  • AbuseIPDB — 414.244 IPs (score 100, 180 dias)

A pergunta

De 48.915 alertas, quantos representam risco real que ainda não foi bloqueado?

O pipeline correlaciona os dois sistemas pelo Community ID, classifica cada fluxo por desfecho e propõe regras via API REST — sem LLM escrevendo direto no firewall.

48.915 alertas.

Problema central

Alerta ≠ ameaça que passou

Se 99,2% das origens já estão na blacklist, a maioria dos alertas descreve tráfego que o PF já bloqueia. Uma regra nova só tem valor sobre o que passa.

Resíduo público

98,6% é reputação, não exploit

1.377 dos 1.397 alertas públicos são assinaturas de reputação (ET CINS, DShield). Isso mede divergência entre listas, não comportamento novo.

Origem privada

82% vem de um host legítimo

6.495 alertas (82% do resíduo) são do host 192.168.15.200 — dispositivo de outra rede gerando falsos positivos de STUN, Discord e DNS.

Trilha interna

6.495 alertas — host legítimo

192.168.15.200 gera falsos positivos de STUN (3.664), DNS .biz (1.009), Discord (647). Não é ataque — é dispositivo na rede.

→ suppress/threshold no Suricata

Trilha reputação

1.377 alertas — divergência de feeds

IPs que estão em uma lista mas não em outra. Medir contribuição exclusiva e latência de cada feed (AbuseIPDB, Spamhaus, DShield).

→ comparar feeds, medir latência

Trilha comportamento

20 alertas — exploit real

8 alertas do Realtek CVE-2021-35394 (exploit ativo). 5 IPs bloqueados via API REST do OPNsense. 12 são STUN/Jabber (legítimo).

→ 5 regras IA-aparecido ativas no PF

03b · Detalhamento técnico

O que cada componente detecta

Separando o que é detectado só pelo PF, só pelo Suricata, pela interseção e o que a IA acrescenta.

Componente O que detecta Cobertura Resultado
🔒 PF sozinho IPs em listas DROP · tráfego sem rota · CIDR hostil 42.804 fluxos 87,3% — base da defesa
📡 Suricata sozinho Assinaturas de exploit · ET CINS · comportamento 48.915 alertas Visibilidade — sem bloqueio
🔗 Interseção PF + Suricata Alertas com desfecho real (Community ID) 6.012 fluxos PASS Elimina falsos alarmes do IDS
🤖 IA (Faro) CVE-2021-35394 Realtek · UDP 9034 · padrão de taxa 8 alertas → 5 regras 0% FP · 100% cobertura Realtek
🛡 CrowdSec IPs com histórico colaborativo em tempo real 8.328 IPs Concorda: 0% incremental

Conclusão do detalhamento

O PF (87,3%) e o CrowdSec cobrem a maior parte automaticamente. O Suricata fornece visibilidade. A IA acrescenta uma camada comportamental que identificou o único exploit real do período sem gerar falso positivo.

04 · Resultados

5 hipóteses testadas com dados reais

H1

Maioria já é bloqueada pelo PF

42.639 (87,2%) em SEM REGISTRO + 165 com bloqueio explícito. O volume superestima o risco real em 87%.

✅ Confirmada
H2

Divergência entre feeds explica os que passam

Os 18 externos que passaram são STUN e Jabber (legítimos), não divergência de listas. Script coletar_feeds.py arquivando snapshots diários.

⚠️ Parcial
H3

Comportamento generaliza melhor que IP individual

IP individual (4.945 regras) = 0% cobertura. Comportamento (169 regras) = 0% cobertura. Os IPs que passam são legítimos — sem resíduo para diferenciar famílias.

❌ Inconclusivo
H4

Pipeline vs. CrowdSec

CrowdSec (8.328 IPs) concorda: 0% cobertura incremental. Ambos chegam à mesma conclusão de forma independente.

✅ Respondida
H5

LLM propõe regras comparáveis às heurísticas

Sem resíduo perigoso, o LLM não tem o que propor. Quando entrar, toda proposta passa pelo simulador antes do firewall. Proteção contra injeção indireta (OWASP LLM01).

⏳ Sem resíduo

Resposta à pergunta de pesquisa

Os fluxos que passam são tráfego legítimo (STUN, Jabber, Discord, DNS, atualizações Linux). O firewall já está funcionando corretamente. O Suricata superestima o risco em 87% — e o CrowdSec confirma de forma independente.
